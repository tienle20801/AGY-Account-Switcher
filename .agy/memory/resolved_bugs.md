# Resolved Bugs & Pitfalls

- **Workspace directory creation**: `run_command` fails with `no such directory` if the workspace root folder does not exist yet. Always create initial files via `write_file` before invoking `run_command` in a fresh workspace.
- **Escaping closure on `inout` parameter (`UsageTrackerService`)**: `String.enumerateLines` uses an escaping closure on Swift 6.4 / Xcode 27.2 SDK, causing a compile error when mutating an `inout` struct parameter inside it. Replaced with `for rawLine in rawContent.split(whereSeparator: \.isNewline)`.
- **Non-Sendable `FileManager` stored property**: Storing `FileManager` in a `Sendable` service class emits a Swift 6 concurrency warning. Replaced with computed property `private var fileManager: FileManager { .default }`.
- **SIGSEGV (signal 11) in `xctest` on `Date` `Comparable` operators (`<`, `>`, `>=`)**: On macOS 27.2 SDK (`swiftlang-6.4.2`) when targeting `.macOS(.v13)` from an executable SwiftPM target, `Date` `Comparable` witness dispatch (`stepDate >= cutoff`) crashed with `SEGV` at `0x0` in `xctest`. Comparing `.timeIntervalSinceReferenceDate` directly avoids the weak-linked witness and passed all tests cleanly.
- **Antigravity 2.0 OAuth & login persistence (`language_server` `go-keyring` + `app_storage.json`)**: Clearing Chromium Cookies/Local Storage alone leaves Antigravity 2.0 signed in because `language_server` stores its OAuth `StoredToken` (`userTier`, `token`, `isGcpTos`, `licenses`) in macOS Keychain (`kSecClassGenericPassword`, `kSecAttrService="gemini"`, `kSecAttrAccount="antigravity"`, encoded via `zalando/go-keyring`) with fallback file `~/.gemini/jetski-standalone-oauth-token`, while the Electron shell persists `"agy.onboarding.lastLoginUsername"` / `"agy.onboarding.lastLoginIsGcpTos"` inside `~/Library/Application Support/Antigravity/app_storage.json` and `credential-user-scope`. Fixed by always backing up, restoring, and clearing `("gemini", "antigravity")` via native `Security` API (`SecItemCopyMatching` / `SecItemUpdate` / `SecItemAdd` with `SecAccessCreate` trusting `/usr/bin/security` and `Antigravity.app` / `SecItemDelete`), stripping onboarding login keys from `app_storage.json` (preserving user workspaces/layouts), syncing `credential-user-scope` and `jetski-standalone-oauth-token`, and stopping any detached `language_server` process before relaunch.
- **Duplicate SwiftUI segmented Picker label (`AddAccountSheetView` & `SettingsInlineView`)**: Adding `.labelsHidden()` hides the redundant `"Gói"` / `"Cửa sổ"` text rendered next to custom row titles.
- **Usage resetting to `0` on every account switch & Dashboard quota mismatch (`retrieveUserQuotaSummary`, `last_step_index`, startup sync)**:
  1. `AccountSwitcherService.switchToAccount` previously overwrote `modelUsages` with `merge` from `lastSwitchedAt = Date()`, zeroing usage on switch. Fixed by flushing incremental deltas before switch and switching to `mergeIncremental`.
  2. `CloudCodeQuotaService` previously failed silently against Cloud Code Assist (`HTTP 400` on `"platform": "MACOS"` instead of `"DARWIN_ARM64"`, missing `User-Agent: antigravity/2.32.0 (darwin/arm64)`, missing `paidTier` check where Google One AI Pro accounts report `currentTier = free-tier` + `paidTier = g1-pro-tier`, and calling `/v1internal:fetchAvailableModels` instead of `/v1internal:retrieveUserQuotaSummary` which powers the 4 official Antigravity buckets `gemini-5h`, `gemini-weekly`, `3p-5h`, `3p-weekly`).
  3. In SQLite `conversations/*.db`, `gen_metadata.idx` does not match `steps.idx`; step timestamps live on `steps.idx = last_step_index` parsed from `gen_metadata.f1.f20` key-value pairs. Also fixed `AGYAutoChangerApp` startup sync (`AppLaunchCoordinator`) + legacy `accounts.json` bucket migration.
- **SQLite `gen_metadata` schema & URI spaces / `SQLITE_STATIC` lifetime**: In Antigravity `conversations/*.db`, generation blobs live in `gen_metadata (idx, data)` while timestamps live in `steps (idx, metadata)` keyed by `f1.f20["last_step_index"]`. Opening DBs via `"\(dbURL.absoluteString)?mode=ro"` handles paths with spaces under `SQLITE_OPEN_URI`, and unit tests using `sqlite3_bind_blob` from `Data.withUnsafeBytes` must pass `SQLITE_TRANSIENT` (`unsafeBitCast(-1, to: sqlite3_destructor_type.self)`) when `sqlite3_step` runs outside the closure.
- **Main-thread hang on macOS Keychain `kSecReturnData: true` after ad-hoc rebuild (`SecItemCopyMatching`)**: Calling `inspectCurrentLiveState(readKeychainSecret: true)` or `querySingleGenericPassword` during `bootstrapOnLaunch()` / passive popover refresh triggers a macOS Keychain ACL prompt (`SecurityServer::ClientSession::decrypt`) whenever the `.app` is rebuilt with a new ad-hoc CDHash. Fixed by keeping `bootstrapOnLaunch()` and `refreshLiveStateAndUsage()` at `readKeychainSecret: false`, checking file/Vault tokens (`keychain_fallback.json` & `jetski_oauth_token`) BEFORE live Keychain in `extractValidBearerToken`, and still running `syncDashboardQuotasForAllAccounts` unconditionally.
- **`MenuBarExtra(.window)` collapses `ViewThatFits` + `ScrollView` to zero height & detaches below the Menu Bar after height shrink (`Settings` -> `Xong`)**: Inside `MenuBarExtra(.window)`, `ViewThatFits(in: .vertical)` with a `ScrollView(.vertical)` fallback collapses the scroll viewport to `0pt` (`82px` total window) when `NSHostingView` probes minimum fitting size, and `_NSMenuBarExtraWindow` anchors Cocoa frames bottom-left so shrinking height leaves a gap under the Menu Bar. Fixed in `AGYAutoChangerApp.swift` + `MenuBarPopoverView.swift` by replacing `MenuBarExtra(.window)` with `MenuBarPanelController` (`NSStatusItem` + borderless `FloatingPopoverPanel` + `SizingHostingView` + `NSVisualEffectView` with 9-slice `maskImage`), computing top-down `originY = anchoredTopY - height` (`4pt` below the Menu Bar), locking `anchoredOriginX` per open session, measuring body height via `PreferenceKey` inside `ScrollView`, and capping height at `0.78` of the active screen's `visibleFrame.height` (`uiPopoverMinWidth = 400`, `uiPopoverIdealWidth = 436`, `uiPopoverMaxWidth = 480`).
- **Smart Auto-Switch `.allSelected` deadlock on same-family sibling windows & slow 120s polling (`SmartAutoSwitchService` + `SettingsInlineView`)**: Monitoring `["gemini-5h", "gemini-weekly"]` with `triggerMatchMode == .allSelected` previously required BOTH `5h` and `weekly` to drop `<= threshold` simultaneously, blocking auto-switch when `gemini-5h` hit `0%` while `gemini-weekly` remained `73%`. Fixed by grouping buckets into model families (`AutoSwitchPolicy.bucketFamilyID`) so `.allSelected` triggers once every selected family has at least one exhausted window, hiding the `.allSelected` picker when `< 2` distinct families are selected, and adding adaptive `45s` / `20s` near-threshold background polling when Smart Auto-Switch is enabled.
